SMD (Slovingo Markdown)
 
SMD est une extension légère du Markdown destinée à créer des fiches d'apprentissage des langues (initialement le slovaque).
 
Il est entièrement compatible avec le Markdown classique et ajoute seulement quelques constructions spécifiques. 
 
---
 
1. Translate-table
 
Une Translate-table est un tableau markdown classique, avec 2 colonnes minimum : mot/expression et traduction. Privilégier la langue apprise dans la première colonne, mais non obligatoire. 
 
Exemple :
 
| Français | Slovaque |
|----------|-----------|
| Bonjour | Dobrý deň |
| Merci | Ďakujem |
 
Si une colonne possède un en-tête contenant un mot désignant la langue apprise (pour le slovaque, par exemple : "Slovaque", "Slovak", "Slovenčina"...), le convertisseur ajoute automatiquement :
 
class="translate-table"
 
Le Javascript se charge ensuite de :
 
- détecter automatiquement cette colonne
- ajouter "class="speakable" à toutes les cellules de cette colonne
- rendre ces cellules prononçables.
 
Aucune syntaxe supplémentaire n'est nécessaire.
 
---
 
2. Audio-card
 
Permet de représenter une phrase avec sa traduction et ses explications.
 
Syntaxe :
 
! Chýbaš mi.
> Tu me manques.
> Chýbaš = tu manques
> mi = à moi
+ La construction est inversée par rapport au français.
 
Règles :
 
- une ligne commençant par "!" ouvre une nouvelle carte audio ;
- le texte après "!" est la phrase à prononcer ;
- le premier ">" est la traduction naturelle ;
- les ">" suivants constituent la traduction littérale ou la décomposition de la phrase ;
- les lignes commençant par "+" sont des remarques, explications ou notes grammaticales ;
- plusieurs lignes ">" et "+" sont autorisées.
 
Marqueur de locuteur (dialogues) :

Dans une fiche dialogue, une audio-card peut être préfixée par un émoji
désignant le locuteur :

! 💬 Vstávali sme na bugel, o siedmej ráno.
> On se levait au clairon, à sept heures du matin.

Règle de détection (voir split_speaker() dans src/smd2data.py) : sur la
ligne "!", le premier "mot" (séparé par un espace) est traité comme
émoji-locuteur s'il ne contient aucun caractère alphabétique. Une section
(H2/H3) entièrement composée d'audio-cards ayant chacune un émoji-locuteur
est automatiquement marquée comme section de dialogue par le convertisseur.

Le convertisseur génère une structure HTML du type :
 
<div class="audio-card">
 
    <div class="audio-text">
        ...
    </div>
 
    <div class="audio-translation">
 
        <div class="natural-translation">
            ...
        </div>
 
        <div class="literal-translation">
            ...
        </div>
 
        <div class="notes">
            ...
        </div>
 
    </div>
 
</div>
 
Le Javascript ajoute automatiquement les boutons (lecture, lecture lente, affichage des traductions...), masque les traductions par défaut et rend la phrase directement cliquable.

3. Élément speakable
 
Permet de rendre prononçable un mot ou une expression au milieu d'un texte.
 
Syntaxe :
 
Le mot {{jeden}} signifie « un ».
 
La phrase {{Ako sa máte?}} est très courante.
 
Le convertisseur remplace :
 
{{texte}}
 
par :
 
<span class="speakable">texte</span>
 
Le Javascript ajoute automatiquement le comportement de lecture.
 
Cette syntaxe peut être utilisée partout (paragraphes, listes, tableaux, cartes audio...).

Langue du speakable (préfixe optionnel) :

Sans préfixe, {{texte}} est lu dans la langue apprise. Un préfixe "xx:" (code
ISO court de lang.json : target_lang.code ou native_lang.code) choisit
explicitement la langue de lecture :

Le mot {{Maus}} signifie « {{fr:souris}} ».
{{de:Guten Tag}} est équivalent à {{Guten Tag}} (langue apprise, explicite).

- {{fr:...}} (langue native) : lu avec la voix native (Réglages > Audio),
  affiché avec un soulignement en pointillés et une icône 🗣️ à la place du 🔊.
- un préfixe qui n'est ni le code de la langue apprise ni celui de la langue
  native (ex. {{Remarque: ...}}) n'est pas interprété : tout le texte est lu
  dans la langue apprise, comme avant.
- lecture au clic uniquement (pas de lecture automatique de la traduction).
- smd2data.py n'a rien de spécial à faire : {{fr:texte}} devient [[fr:texte]]
  dans le JSON, le préfixe est interprété par le Javascript (renderText() dans
  app.js) à partir de lang.json.
- limite connue : dans une audio-card, la phrase entière est lue avec la voix
  de la langue apprise ; un {{fr:...}} placé dans le texte de la phrase ("!")
  n'est donc pas lu à part. L'utiliser dans les traductions, remarques,
  paragraphes, listes et tableaux.

4. Illustration

Permet d'ajouter une image en tête de fiche (ou, plus rarement, au milieu du contenu). Deux syntaxes équivalentes sont acceptées :

Syntaxe SMD :

@ img/fichier.jpg | Légende

Syntaxe Markdown classique (également supportée) :

![Légende](img/fichier.jpg)

ou, avec un titre distinct de l'alt-text (le titre est alors utilisé comme légende) :

![alt](img/fichier.jpg "Légende")

Les deux formes produisent :

<figure class="fiche-illustration">
    <img src="img/fichier.jpg" alt="Légende">
    <figcaption>Légende</figcaption>
</figure>

Le caractère @ est choisi pour ne pas entrer en collision avec "!" (audio-card), ">" (traduction), "+" (remarque). Voir Fiches-Serie.txt pour le détail du workflow éditorial (sourcing Wikimedia Commons, rapatriement local des images).

5. Carte géographique

Permet d'insérer une carte Leaflet avec une ou plusieurs épingles, ou un trajet. Chaque ligne commence par "%" (caractère libre : pas de collision avec "!", ">", "+", "@").

Une épingle :

% 48.1486, 17.1077 | Bratislavský hrad

Un trajet (une ligne d'en-tête "%~" relie les points dans l'ordre, numérotés) :

%~ Du centre au château
% 48.1440, 17.1070 | Hlavné námestie
% 48.1470, 17.1000 | Michalská brána
% 48.1486, 17.1077 | Hrad

Plusieurs épingles avec un titre, sans trajet (en-tête "%:") :

%: Les Hautes Tatras
% 49.1795, 20.0880 | Tatranská Lomnica
% 49.1190, 20.0090 | Štrbské Pleso

Règles :
- Lignes "%" consécutives = une seule carte. Une ligne vide, ou toute autre ligne, termine la carte.
- L'en-tête ("%~ titre" ou "%: titre") est facultatif. Sans en-tête : épingles seules, sans titre.
- Une ligne de point : "% latitude, longitude" (degrés décimaux, point comme séparateur), puis des champs facultatifs séparés par "|" :
    libellé          texte affiché dans la bulle de l'épingle
    zNN              zoom (1 à 19), ex. z15
    mot-clé de fond  osm (défaut), topo (relief), light, dark
- Le zoom et le fond valent pour toute la carte ; la première occurrence l'emporte. On les met d'habitude sur la première ligne :
    % 49.17, 20.09 | Tatry | z12 | topo
- Sans zoom, la carte s'ajuste automatiquement à l'ensemble des points.
- Le libellé accepte {{...}} comme le reste du texte, mais ne doit pas contenir de "|".
- Une ligne "%" mal formée (coordonnées hors limites) est ignorée avec un avertissement du build.

Pour trouver les coordonnées et générer ces lignes : ouvrir tools/geomap-editor.html dans un navigateur (clic sur la carte ou recherche d'un lieu, réglage du fond, du trajet et du zoom), puis copier le code généré dans la fiche .md. L'éditeur sait aussi recharger un bloc existant.

Fonds de carte : OpenStreetMap, OpenTopoMap, CARTO clair/sombre. Aucune clé n'est nécessaire, l'attribution est affichée sur chaque carte et ne doit pas être retirée. Leaflet est embarqué dans static/vendor/leaflet/ et précaché par le service worker ; les tuiles, elles, viennent du réseau (hors-ligne, la carte est remplacée par la liste des points).

Rendu : le bloc devient {"type": "geomap", "title", "route", "zoom", "layer", "points": [{"lat", "lon", "label"}]} dans data.json, affiché par static/geomap.js.

Résumé de la syntaxe
 
Syntaxe| Signification
`| ...
"!"| Début d'une audio-card
premier ">"| Traduction naturelle
autres ">"| Traduction littérale / décomposition
"+"| Remarques, notes, explications
"{{...}}"| Élément prononçable (speakable), langue apprise
"{{fr:...}}"| Élément prononçable en langue native (préfixe = code ISO)
émoji en tête de "!"| Marqueur de locuteur (dialogues)
"@ url \| légende" ou "![alt](url)"| Illustration
 
---
 
Philosophie
 
Le contenu SMD reste lisible en texte brut.
 
Le fichier SMD ne contient aucune information de présentation ni de comportement.
 
Le convertisseur produit un HTML sémantique.
 
Le CSS gère la présentation.
 
Le Javascript ajoute le comportement interactif (lecture audio, boutons, affichage des traductions, recherche, etc.).
 
Cette séparation permet de faire évoluer librement le rendu HTML, le CSS ou le Javascript sans modifier les fichiers SMD.
